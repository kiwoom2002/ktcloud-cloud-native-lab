# 02. 기술 키워드별 정리

[← 01. 과목별 학습 내용](./01-과목별-학습-내용.md) · [학습 정리](./README.md)

자기소개서·면접에서 **"회사에 기여할 수 있는 기술"** 로 바로 쓸 수 있게 키워드별로 정리했습니다. 키워드마다 **기여할 수 있는 기술(결론) → 근거가 된 실습 → 연결되는 다른 경험** 순서입니다.
근거는 모두 이 저장소의 실습·미션 문서이고, 저장소에서 확인되지 않는 기술(예: Terraform)은 "다루지 않음"으로 적었습니다.

| 키워드 | 기여할 수 있는 기술 (한 줄) |
|---|---|
| [REST API](#1-rest-api) | 상태 코드와 헬스 체크 엔드포인트를 갖춘 API를 컨테이너·쿠버네티스 환경에서 운영 가능한 형태로 만듭니다 |
| [컨테이너 (Docker)](#2-컨테이너-docker) | 캐시를 살린 Dockerfile과 Compose로 개발·운영 환경 차이를 없앱니다 |
| [쿠버네티스](#3-쿠버네티스-kubernetes) | Probe·자원 제한·롤링 업데이트로 무중단 배포와 자가 복구를 설계하고, 장애를 순서대로 진단합니다 |
| [CI/CD](#4-cicd) | 테스트·보안 스캔 게이트가 있는 파이프라인으로 검증된 이미지만 배포되게 합니다 |
| [GitOps](#5-gitops) | 배포와 롤백을 Git 커밋 하나로 다루고, dev 자동 / prod 승인으로 환경을 분리합니다 |
| [MSA](#6-msa-마이크로서비스) | 서비스 11개 규모의 마이크로서비스를 배포·격리·관측하며 서비스 간 의존 관계를 다룹니다 |
| [IaC · 선언형 구성](#7-iac--선언형-구성-관리) | 인프라와 배포 설정을 YAML·Helm values·Kustomize overlay로 코드화해 재현 가능하게 관리합니다 |
| [DevSecOps](#8-devsecops--클라우드-보안) | 이미지 스캔·서명, 최소 권한, 네트워크 격리, 정책 엔진으로 보안을 파이프라인과 클러스터에 내장합니다 |
| [서비스 메시](#9-서비스-메시) | 코드 변경 없이 mTLS·카나리·타임아웃·재시도를 적용합니다 |
| [관측성 · SRE](#10-관측성-observability--sre) | 지표·로그·트레이스로 장애 원인을 좁히고, SLO와 오류 예산 기반 경보를 설계합니다 |

## 1. REST API

**기여할 수 있는 기술: 리소스 중심 엔드포인트와 정확한 HTTP 상태 코드, 헬스 체크·지표 엔드포인트를 갖춘 API를 컨테이너 환경에서 안정적으로 운영할 수 있게 만듭니다.**

- 실습 앱 todo-api(`lab/docker/todo/api/app.js`, Node.js Express + PostgreSQL)
  - `GET /api/todos` · `POST /api/todos`(201 Created, 입력 검증 실패 시 400) · `DELETE /api/todos/:id`(204 No Content)
  - `GET /api/health` 헬스 체크 → 쿠버네티스 readiness/liveness Probe 대상
  - 파라미터 바인딩(`$1`)으로 SQL 인젝션 방지, DB 연결 타임아웃 3초·재시도로 기동 순서 문제 처리
- nginx 리버스 프록시로 `/api/` 요청을 API 서버로 전달(`lab/docker/todo/web/default.conf`)
- 모니터링 과목에서 API에 `/metrics`를 직접 달아 **경로별 요청 수·지연**을 수집 (모니터링 실습 4)
- **연결되는 경험**: JSP/Servlet + JDBC + MySQL 셔틀버스 예약 시스템(중복 예약 방지, 좌석 수 정합성), Java Servlet 주차관리 시스템, 화재방지 로봇의 서버 API 연동, SQLD

## 2. 컨테이너 (Docker)

**기여할 수 있는 기술: 빌드 캐시를 고려한 Dockerfile과 Compose 기반 멀티 컨테이너 구성으로 "내 PC에선 되는데" 문제를 없애고 빌드 시간을 줄입니다.**

- 레이어 캐시를 살리는 `COPY` 순서(의존성 먼저 → 소스 나중), `npm ci --omit=dev`, `.dockerignore` (Docker 실습 7·8)
- 볼륨(데이터 영속성) vs 바인드 마운트(개발 중 즉시 반영) 구분 (Docker 실습 10·11)
- 사용자 정의 네트워크에서 컨테이너 이름 기반 통신, Compose로 3티어(web · api · db) 일괄 관리 (Docker 실습 12·13)
- 레지스트리 운영: Docker Hub, GHCR, 로컬 레지스트리 (Docker 실습 9, CI/CD 실습 3, 보안 실습 10)

## 3. 쿠버네티스 (Kubernetes)

**기여할 수 있는 기술: Probe·requests/limits·롤링 업데이트를 갖춘 매니페스트로 무중단 배포와 자가 복구를 설계하고, 장애가 나면 `get → describe → logs → 엔드포인트` 순서로 원인을 찾습니다.**

- Deployment(자가 복구·스케일), 롤링 업데이트와 `rollout undo` 롤백, 잘못된 이미지 배포 시에도 기존 Pod가 서비스 유지 (K8s 실습 4·5)
- Service(ClusterIP·NodePort)·Ingress(Traefik) 호스트 기반 라우팅 (K8s 실습 6·11)
- ConfigMap / Secret으로 설정 분리, PVC로 DB 데이터 영속화 (K8s 실습 7·8)
- readiness/liveness Probe, requests/limits, `Pending`·`OOMKilled` 재현, HPA (K8s 실습 9·10)
- Helm으로 서비스 11개 일괄 설치·업그레이드·롤백 (K8s 실습 12)
- **트러블슈팅**: 숨은 장애 6개를 찾아 고친 미션 (K8s 미션 2)

## 4. CI/CD

**기여할 수 있는 기술: 테스트와 보안 스캔을 통과한 이미지만 레지스트리에 올라가는 파이프라인을 GitHub Actions와 Jenkins 양쪽으로 구성할 수 있습니다.**

- GitHub Actions: `paths` 필터, `npm test` → `docker/build-push-action` → GHCR, `GITHUB_TOKEN` + `permissions: packages: write`로 시크릿 없는 레지스트리 인증 (CI/CD 실습 3)
- 이미지 태그를 **커밋 SHA**로 붙여 배포 이미지와 소스 코드를 1:1 추적 (CI/CD 실습 3)
- `test` / `scan` / `push` job 분리, `trivy image --exit-code 1 --severity CRITICAL --ignore-unfixed` **보안 게이트**, PR에서는 검사만·main에서만 업로드 (CI/CD 실습 4)
- Jenkins(JCasC) + `Jenkinsfile`: 테스트 → 빌드 → 스캔 → 올리기 → **매니페스트 태그 갱신 커밋**, Credentials로 토큰 관리 (CI/CD 실습 5)
- 정적 파일 서비스는 `nginx -t`를 테스트 단계로 사용 (CI/CD 미션 1)

## 5. GitOps

**기여할 수 있는 기술: Git을 배포의 단일 진실 공급원(Single Source of Truth)으로 두고, 배포와 롤백을 커밋 하나로 처리하며 운영 환경 반영은 PR 승인으로 통제합니다.**

- Argo CD Application: 저장소 `deploy/overlays/dev` → `todo-dev`, `automated` + `selfHeal: true`로 수동 변경(drift)을 Git 상태로 자동 복구 (CI/CD 실습 6)
- push → Jenkins가 `jenkins-N` 이미지 빌드·태그 커밋 → Argo CD 배포, 문제 시 매니페스트 커밋 `git revert`로 롤백 (CI/CD 실습 7)
- **환경별 승격**: dev는 자동 배포, prod(`todo-prod`)는 dev에서 검증된 태그만 PR 승인 후 Sync (CI/CD 미션 2)

## 6. MSA (마이크로서비스)

**기여할 수 있는 기술: 언어가 다른 서비스 11개로 된 마이크로서비스(Online Boutique)를 Compose → 쿠버네티스 → Helm으로 옮기며 배포하고, 서비스 단위로 격리·트래픽 제어·관측할 수 있습니다.**

- Compose로 서비스 5~6개 조립 → Deployment + Service로 마이그레이션 → Helm 차트로 11개 일괄 설치 (Docker 미션 2, K8s 미션 1, K8s 실습 12)
- 서비스 간 호출 경로만 열어 두는 네임스페이스 격리(Traefik → frontend, cartservice → redis-cart) (보안 미션 2)
- Kiali 서비스 관계도로 호출 의존성 파악, 카나리 배포로 서비스 단위 점진 릴리스 (서비스 메시 실습 4·6)
- 앱 수정 없이 사이드카 지표로 서비스별 골든 시그널 대시보드 구성 (모니터링 미션 1)

## 7. IaC · 선언형 구성 관리

**기여할 수 있는 기술: 클러스터·배포·도구 설정을 모두 버전 관리되는 코드(YAML, Helm values, Kustomize overlay, JCasC)로 두어 몇 분 만에 같은 환경을 다시 만들 수 있게 관리합니다.**

- 클러스터 정의 `lab/kind/lite.yaml`·`full.yaml`, 도구 버전 고정 `lab/.mise.toml`, `make up / reset`으로 환경 재생성
- 구성 요소별 Helm values 관리(`lab/argocd/values.yaml`, `lab/monitoring/*-values.yaml`, `lab/ingress/traefik-values.yaml`) 와 차트 버전 고정(`lab/Makefile`)
- Kustomize `deploy/overlays/dev`·prod로 환경별 매니페스트 분리 (CI/CD 실습 6, 미션 2)
- Jenkins 설정을 코드로: `lab/jenkins/casc.yaml`(JCasC), `plugins.txt`
- 정책도 코드로: Kyverno `ValidatingPolicy`, 경보·SLO 규칙 `PrometheusRule` (보안 실습 9, 모니터링 실습 8)
- **다루지 않음**: Terraform·CloudFormation 같은 클라우드 리소스 프로비저닝 도구는 이 저장소에 없습니다. 면접에서는 "선언형 구성 관리와 GitOps를 실습했고, 같은 원리를 Terraform으로 확장할 수 있다" 수준으로 말하는 것이 정확합니다

## 8. DevSecOps · 클라우드 보안

**기여할 수 있는 기술: 빌드(스캔·SBOM·서명) → 배포(정책 엔진·PSA) → 런타임(SecurityContext·RBAC·NetworkPolicy) 단계마다 보안 통제를 넣어, 보안 점검을 사람이 아닌 파이프라인과 클러스터가 하게 만듭니다.**

- 빈틈 재현: root 실행 + 열린 네트워크 + 자동 마운트 토큰을 이어 다른 네임스페이스에서 데이터를 읽고 지우는 공격 경로 확인 (보안 실습 1)
- Trivy 이미지·설정 스캔, non-root 하드닝 이미지, `runAsNonRoot`·`readOnlyRootFilesystem`·`allowPrivilegeEscalation: false`·`capabilities.drop: [ALL]` (보안 실습 2~4)
- Secret 파일 마운트(`defaultMode: 0400`), `automountServiceAccountToken: false` (보안 실습 5)
- RBAC 최소 권한, `kubectl auth can-i`로 권한 검증 (보안 실습 6)
- NetworkPolicy default deny + 필요한 경로만 허용 (보안 실습 7)
- Pod Security Admission `restricted`, Kyverno로 latest 태그 금지 (보안 실습 8·9)
- **공급망 보안**: SBOM(CycloneDX/SPDX) 생성·스캔, cosign 서명·검증으로 태그 덮어쓰기 탐지 (보안 실습 10)
- 같은 Trivy 스캔을 CI 게이트로 자동화 (CI/CD 실습 4)

## 9. 서비스 메시

**기여할 수 있는 기술: 애플리케이션 코드를 바꾸지 않고 서비스 간 mTLS, 신원 기반 인가, 카나리 트래픽 분할, 타임아웃·재시도를 적용해 배포 위험과 장애 전파를 줄입니다.**

- Linkerd: 프록시 주입만으로 성공률·RPS·지연 관측, mTLS 자동 적용 (메시 실습 1·2)
- ServiceAccount 인증서 기반 인가 — 라벨을 위장한 Pod도 차단 (메시 실습 3)
- Istio DestinationRule + VirtualService로 v1 90% / v2 10%, `x-canary: true` 헤더 라우팅 (메시 실습 4)
- 장애 주입으로 지연·오류 재현 후 타임아웃·재시도 적용 (메시 실습 5)
- Kiali 관계도, `istioctl analyze`로 메시 설정 오류 4개 진단 (메시 실습 6, 미션)

## 10. 관측성 (Observability) · SRE

**기여할 수 있는 기술: 지표로 "무엇이", 로그로 "언제부터 어떤 요청이", 트레이스로 "어디서" 나빠졌는지 좁혀 원인을 찾고, SLO와 오류 예산 소진 속도 기반 경보로 사용자보다 먼저 장애를 알아차립니다.**

- kube-prometheus-stack(Prometheus · Grafana · Alertmanager), PromQL `rate`·`sum by`·`histogram_quantile`(p95)·`topk` (모니터링 실습 1~3)
- 앱 계측(`/metrics`) + ServiceMonitor, 요청 수·p95·5xx 비율 대시보드 (모니터링 실습 4·5)
- Alloy + Loki 중앙 로그 수집, LogQL, JSON 로그 필드 필터 (모니터링 실습 6)
- Tempo 분산 트레이싱 — Istio 사이드카 스팬을 OTLP로 전송, 구간별 지연 분석 (모니터링 실습 7)
- 경보 규칙(frontend 5xx 1분간 10% 초과) → Alertmanager 라우팅, **SLO 99.5%** 가용성 SLI와 burn rate 기록 규칙 (모니터링 실습 8)
- 관측 도구만으로 장애 원인을 찾고 **장애 보고서** 작성 (모니터링 미션 2)

## 내 다른 경험과 묶어 말하기

| 경험 | 함께 쓸 키워드 |
|---|---|
| 셔틀버스 예약 시스템 (JSP/Servlet, Tomcat, JDBC, MySQL) — 중복 예약 방지, 좌석 수 정합성 | REST API, DB 트랜잭션 → 컨테이너·쿠버네티스 배포로 확장 |
| 주차관리 시스템 (Java Servlet, MySQL, Tess4J OCR, Arduino Serial) | 서버–DB–장치 연동 → 관측성(어느 구간이 느린지 트레이싱) |
| 데이터센터 화재방지 로봇 (YOLO, TensorRT, 서버 API 연동) | API 연동, 추론 성능 최적화 → 컨테이너화·리소스 제한·모니터링 |
| SQLD, 정보처리기사 | 데이터 모델링·SQL, 소프트웨어 공학 기초 |
